### 🔥 정리하기

#### 1. 제네릭이란
제네릭은 타입을 미리 정의하지 않고 사용하는 시점에 원하는 타입을 정의해서 쓸 수 있는 문법

#### 2. 제네릭 기본 문법
```javascript
function getText<T>(text: T) {
  return text;
}

function getText(text: number): number {
  return text;
}
```

#### 3. 왜 제네릭을 사용할까?
1. 중복되는 타입 코드의 문제점
반복되는 코드를 줄여주는 장점이 있다.

아래 코드는 동일한 기능을 수행하지만 타입으 다르다는 이유로 중복되어 정의되는 문제점이 있다.
```javascript
function getText(text: string): string {
  return text;
}

function getNumber(num: number): number {
  return num;
}
```

2. any를 쓰면 되지 않을까?
- any를 사용하면 타입스크립트를 사용하는 이유가 없다.

3. 제네릭으로 해결되는 문제점
```javascript
function getText<T>(text: T): T {
  return text
}
```
#### 4. 인터페이스에 제네릭 사용하기
```javascript
interface ProductDropdown {
  value: string;
  selected: boolean;
}

interface StockDropdown {
  value: number;
  selected: boolean;
}

interface AddressDropdown {
  value: { city: string; zipCode: string };
  selected: boolean;
}

interface Dropdown<T> {
  value: T
  selected: boolean
}
```

#### 5. 제네릭의 타입 제약
1. extends를 사용한 타입 제약
```javascript
function embraceEverything<T extends string>(thing: T): T {
  return thing
}

embraceEverything<string>('hi')
embraceEverything<number>('hi') // 에러 발생
```

2. 타입 제약의 특징
```javascript
function lengthOnly<T extends { length: number }>(value: T) {
  return value.length
}

lengthOnly('hi');
lengthOnly([1, 2, 3]);
lengthOnly({ title: 'abe', length: 123});
```

3. keyof를 사용한 타입 제약
keyof는 특정 타입의 키 값을 추출해서 문자열 유니언 타입으로 반환

```javascript
const wook = {
  name: 'wook',
  skill: 'js
}
```

```javascript
type DeveloperKeys = keyof { name: string; skill: string }
type DeveloperKeys = 'name' | 'skill'
```

아래 함수에서 인자로 사용할 수 잆는 값은 name과 skill뿐임
```javascript
function printKey<T extends keyof { name: string; skill: string; }>(value: T) {
  console.log(value)
}
```

#### 6. 제네릭을 처음 사용할 떄 주의해야 할 사고방식
컴파일러 입장에선 제네릭을 써도 어떤 타입이 들어올지는 런타임 시점에 알 수 있다.
따러서 extends를 통해 length 속성을 사용한다는 것을 컴파일러에 알려줘야한다.

```javascript
function printTextLength<T>(text: T) {
  console.log(text.length);
}

printTextLength<string>('hello')
```
